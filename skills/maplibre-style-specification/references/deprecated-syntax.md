# Deprecated syntax: functions and legacy filters

Older styles (and many styles generated by tools) use **functions** (`{"stops": ...}`) and **legacy filters** (`["==", "class", "park"]`). Both still work, but expressions are preferred, and mixing old and new forms can behave unexpectedly. Convert legacy syntax when you edit a style.

Automatic conversion:

```bash
npx --package @maplibre/maplibre-gl-style-spec gl-style-migrate old-style.json > new-style.json
```

## Functions

A function is an object instead of a plain value. Expressions replaced them in GL JS 0.41.0.

| Key | Meaning |
|---|---|
| `stops` | Array of `[input, output]` pairs. Required except for `identity`. Outputs must be literals. |
| `property` | Feature property used as input. If absent, the input is zoom (a zoom function). |
| `base` | Exponential base, default `1` (linear). |
| `type` | `exponential` (default for interpolatable properties), `interval` (step; default for others), `categorical` (exact match), `identity` (returns the property value). |
| `default` | Fallback when the property is missing, not numeric, does not match a category, or is invalid. If absent, the property's default is used. |
| `colorSpace` | `rgb` (default), `lab`, or `hcl` for color interpolation. |

As with expressions, layout-property zoom functions change only at integer zooms.

### Conversions

| Function | Expression |
|---|---|
| `{"stops": [[5, 1], [10, 2]]}` | `["interpolate", ["linear"], ["zoom"], 5, 1, 10, 2]` |
| `{"base": 1.5, "stops": [[5, 1], [10, 4]]}` | `["interpolate", ["exponential", 1.5], ["zoom"], 5, 1, 10, 4]` |
| `{"type": "interval", "stops": [[0, "a"], [10, "b"]]}` (zoom) | `["step", ["zoom"], "a", 10, "b"]` |
| `{"property": "temperature", "stops": [[0, "blue"], [100, "red"]]}` | `["interpolate", ["linear"], ["get", "temperature"], 0, "blue", 100, "red"]` |
| `{"property": "kind", "type": "categorical", "stops": [["a", "#f00"], ["b", "#0f0"]], "default": "#000"}` | `["match", ["get", "kind"], "a", "#f00", "b", "#0f0", "#000"]` |
| `{"property": "color", "type": "identity"}` | `["get", "color"]` (wrap with `to-color` or `coalesce` for a default) |
| `{"type": "interval", "stops": [[2, "{ABBREV}"], [4, "{NAME}"]]}` on `text-field` | `["step", ["zoom"], ["get", "ABBREV"], 4, ["get", "NAME"]]` (below zoom 2 the function uses the first stop too) |

**Zoom-and-property functions** use stops keyed by `{zoom, value}`:

```json
"circle-radius": {
  "property": "rating",
  "stops": [[{"zoom": 0, "value": 0}, 0], [{"zoom": 0, "value": 5}, 5],
            [{"zoom": 20, "value": 0}, 0], [{"zoom": 20, "value": 5}, 20]]
}
```

become a zoom interpolation whose outputs are property interpolations:

```json
"circle-radius": ["interpolate", ["linear"], ["zoom"],
  0, ["interpolate", ["linear"], ["get", "rating"], 0, 0, 5, 5],
  20, ["interpolate", ["linear"], ["get", "rating"], 0, 0, 5, 20]]
```

## Token strings

`"text-field": "{name}"` and `"icon-image": "{class}_11"` substitute feature properties into strings. Replace them with `["get", "name"]` and `["concat", ["get", "class"], "_11"]`. Tokens also appear as `"{name:latin}\n{name:nonlatin}"` in OpenMapTiles styles: `["concat", ["get", "name:latin"], "\n", ["get", "name:nonlatin"]]` (or use `coalesce` to avoid printing empty lines).

## Legacy filters

| Legacy | Meaning | Expression |
|---|---|---|
| `["has", key]` | Property exists | `["has", key]` (same) |
| `["!has", key]` | Property missing | `["!", ["has", key]]` |
| `["==", key, v]` | Equal | `["==", ["get", key], v]` |
| `["!=", key, v]` | Not equal | `["!=", ["get", key], v]` |
| `[">", key, v]`, `[">=", ...]`, `["<", ...]`, `["<=", ...]` | Comparisons | `[">", ["get", key], v]` |
| `["in", key, v0, ..., vn]` | In set | `["in", ["get", key], ["literal", [v0, ..., vn]]]` or `["match", ["get", key], [v0, ..., vn], true, false]` |
| `["!in", key, v0, ..., vn]` | Not in set | `["!", ["in", ["get", key], ["literal", [v0, ..., vn]]]]` |
| `["all", f0, ..., fn]` | AND | `["all", ...]` (same) |
| `["any", f0, ..., fn]` | OR | `["any", ...]` (same) |
| `["none", f0, ..., fn]` | NOR | `["!", ["any", f0, ..., fn]]` |

Special keys:

| Legacy key | Expression |
|---|---|
| `"$type"` (values `Point`, `LineString`, `Polygon`) | `["geometry-type"]` |
| `"$id"` | `["id"]` |

Example:

```json
["all", ["==", "class", "street_limited"], [">=", "admin_level", 3], ["!in", "$type", "Polygon"]]
```

becomes

```json
["all",
  ["==", ["get", "class"], "street_limited"],
  [">=", ["get", "admin_level"], 3],
  ["!=", ["geometry-type"], "Polygon"]]
```

Notes:

- Legacy comparisons are strictly typed, like expressions: `["==", "level", "2"]` does not match the number `2`.
- The renderer guesses which syntax a filter uses. `["==", "class", "park"]` is read as legacy because its second element is a plain string. Expression filters always use `["get", ...]` for property access, so write them that way and never mix the forms within one filter.
- Old styles may also contain `ref` layers (layers that copy `type`, `source`, `source-layer`, `minzoom`, `maxzoom`, `filter`, and `layout` from another layer). They are a v7 holdover. `gl-style-migrate` does not expand them; use `derefLayers(layers)` from the `@maplibre/maplibre-gl-style-spec` JS package, or copy the properties by hand. `gl-style-migrate` also rewrites non-standard colors such as `hsl(900, 0.15, 90%)` into valid CSS.
